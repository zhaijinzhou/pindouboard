# 拼豆出图小程序

把照片变成可施工的拼豆图纸 —— 像素化、CIE Lab ΔE 色号匹配、去背景、杂色合并、分板导出与用量清单。

**核心特性：图像处理 100% 在本机完成，图片不上传任何服务器。**

## 处理链

严格按开发文档 §2 的时序执行：

```
选图 → 校验 → [按取景区域 drawImage 取像素] → 压缩到处理上限
      → 像素化(高采样) → 区域聚合(主导色/均值) → [增强] → [去背景] → [抖动]
      → 色号匹配 → 颜色数上限 → [杂色合并] → 孤立块检测 → 体检 → 统计
```

> ⚠️ **去背景必须在用量统计之前**，否则清单数量虚高。该约束由 `tools/test-core.js` 断言守护。

> ⚠️ **主导色算法必须在高采样格点阵上做频次统计**。每格仅 1 个子样本时它会退化成
> 均值算法，`cartoon` 与 `photo` 输出完全相同。正式链路 `sampleScale=3`，预览链路 `=2`。

### 两条处理链路

| | 预览（配置页） | 正式（editor 页） |
|---|---|---|
| 入口 | `core/preview.js` | `core/pipeline.js` |
| 像素源 | 降采样至最长边 220px（**缓存复用**） | 原图压缩至 1400px |
| `sampleScale` | 2 | 3 |
| 耗时 | **< 120ms**（实测断言） | 数百毫秒 |
| 用途 | 调参时即时反馈 | 最终图纸 |

预览降级策略：预览失败不阻断主流程，仍可点「生成图纸」走完整链路。

## 关键技术决策

| 项 | 决策 | 依据 |
|---|---|---|
| 框架 | 原生小程序 | 性能热点在Canvas/文件 API，跨端框架只增加适配层 |
| 算法库 | 全部自实现 | 零依赖，core 层可在 Node 直接跑单测 |
| 色差 | CIE **ΔE2000** | 修正 ΔE76 在蓝绿区的偏差；已用 Sharma 官方数据验证（偏差 1e-15） |
| 匹配剪枝 | 色相预筛 + ΔE76 粗筛 → ΔE2000 精算 | 52 格场景从 60 万次降至约 2 万次精算 |
| 杂色合并 | ΔE 阈值 **12** | 越过 CIE「明显差异」界线，肉眼难辨又能压颜色数 |
| 主导色 | 格内 3×3 子采样 + 32 级量化，频次 <3 回退均值 | 量化步长需兼顾噪点合并与渐变保留 |
| 存储 | 色号字典 + **RLE** | 实测稀疏键值反而大 114%（见决策文档 Q-04） |
| 导出 | 三级：单图 → 分板 → 降级 | 机型相关尺寸上限 + OffscreenCanvas 非全量可用 |

完整依据见 `docs/决策补充文档.md`。

## ⚠️ 上线前必读

### 色库色值是占位值

`miniprogram/data/colors/mard.json` 中的 RGB **按色名推算，仅用于打通开发流程，禁止直接用于生产**。

校色流程：

1. 采购 MARD 221 色豆（5mm + 2.6mm 双规格）
2. 用色彩管理型取色器在**固定色温与照度**下，每色取 5 颗不同位置求均值
3. 填入 `miniprogram/data/colors/raw/mard-measured.csv`：
   ```csv
   code,name,r,g,b
   H1,纯白,252,251,248
   ```
4. 执行 `npm run build:palette` 覆盖占位值

无实测数据时构建脚本会输出醒目告警。
